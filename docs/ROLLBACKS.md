# Реестр откатов — одна строка .env + рестарт

Каждый пакет несёт свой kill-switch. Строка ниже = «выключить пакет, вернуть прежнее
поведение», без отката кода. После правки .env — рестарт в тихое окно (гейт: 180с без
SPECFIRE-активности/выстрелов, HEAD == ожидаемому).

## ПРЕДУСЛОВИЕ ДЕПЛОЯ: фоновый индекс цепи (#110, р-4)

Без этого пакет НЕ ПОДНИМЕТСЯ (намеренно) либо снимет с себя приёмку ложной тревогой. Три
строки, все — в `.env` боевой машины, кода не касаются.

1. **`CHAIN_INDEX_RPC_URL` обязана быть задана явно.** Порядок выбора узла после р-3 —
   `CHAIN_INDEX_RPC_URL` → `BG_RPC_URL_2` → **ОТКАЗ с названной причиной**: садиться на
   триггерный ключ (`BG_RPC_URL`/`PREDICT_RPC_URL`, где живут predict-полл, preconf-цены и кэш
   позиций) индексу запрещено. Отказ громкий (ERROR на старте + `CHAIN-INDEX: НЕ ПОДНЯТ` в
   hot-stats), но приёмки (а) и (в) без этой переменной недостижимы ПО ПОСТРОЕНИЮ.
2. **Годится бесплатный `https://base-rpc.publicnode.com`** — он умеет `eth_getBlockReceipts`
   (проверено живым запросом), а `https://mainnet.base.org` НЕ умеет (`-32601`), и на нём
   `index_hits` будет нулевым ЗАКОННО, то есть весь вклад #109 не проявится.
3. **Этот же URL не должен стоять ни в `COMBAT_FAILOVER_URLS`, ни в `RPC_URL`**: иначе бой
   штатно садится на ключ индекса, индекс так же штатно уступает — и первый час приёмки «а»
   уходит в строки `УСТУПКА КЛЮЧА БОЮ активна` вместо `ЧИТАЮ ЦЕПЬ`. Совпадение с боевым
   `RPC_URL` — прямой отказ подъёма.

ЧТО ЧИТАТЬ ПОСЛЕ РЕСТАРТА (дословно): `CHAIN-INDEX ПРИЁМКА(60с): … — ВЕРДИКТ: ЖИВ` **либо**
законное `ВЕРДИКТ: ЧАСТИЧНО — цепь читаю, но: ПОЛНЫХ чтений в окне не было …` (при
`CHAIN_INDEX_FULL_ON_LOGS=0` в штиль это ПРОХОД, а не провал), плюс не менее ДВУХ подряд
`CHAIN-INDEX ЖИВОСТЬ(120с): … — ЧИТАЮ ЦЕПЬ` (`подряд здоровых>=2` в самой строке) и НИ ОДНОЙ
строки со словом `ЗАМОРОЖЕН` за первый час.

Принцип (kelbic, 31.07): тривиально обратимое изменение с измеримым эффектом не ждёт
«данных ради данных» — ждать стоит только там, где само ожидание производит статистику
(например, P(win) после 10 окон). Каждый новый пакет обязан добавить сюда свою строку.
