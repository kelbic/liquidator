=== Г2 — ДОРАБОТАТЬ ===
Причина двухчастная. Главный фикс #1 (потолок = подтверждённая голова, снятие вечного латча) закрыт ПО-НАСТОЯЩЕМУ — подтверждён живьём тремя линзами независимо, эту часть не переоткрывать. Но мержить нельзя: весь ДЕНЕЖНЫЙ вклад индекса структурно мёртв, а дефолтный выбор ключа опасен.
Блокеры по важности:
1. Беспрефиксный хэш (chain_index.py:633/693/710/756): receipts_for навсегда {}, state='absent' на севшие пробы, index_hits=0, probe_tip_match структурно 0 — приёмка (в) недостижима ПО ПОСТРОЕНИЮ, noreceipt_dropped_confirmed лжёт. Подтверждено мной запуском. Фикс: нормализация на швах + тест, которому хэш даёт НАСТОЯЩИЙ presign_ladder, не литерал.
2. index_url_choice дефолтом садит 91k зап/сут на ключ №1 — защищённую триггерную ногу (predict/preconf/кэш) — с надписью «разведён» (повтор класса #33). Фикс: явный CHAIN_INDEX_RPC_URL, отказ садиться на ключ predict без явной ручки.
3. probe_no_agg: при пустом primary_map эвристика попадает в probe_judged/in_band/tip_match без маркера — приёмка (б) проходится замером против ЧУЖОГО транзита. Фикс: probe_judged_blind + probe_no_agg==0 в критерий (б).
4. _agg_of_market берёт только BF1-ногу — в up-окне свой транзит = foreign, строка ПОЗИЦИИ не печатается, fat-окно потрачено впустую. Фикс: ключ владения по НАБОРУ ног рынка.
5. Застрявшая голова узла морозит индекс МОЛЧА (selfcheck одноразовый). Фикс: fresh=False при blocks>0 = ERROR в 120с-строке.
6. GIL 40-46мс на полный разбор заторного блока — включается по построению 30с после каждой пробы, на одном ядре против призового 200мс-сегмента; замер трафика занижен в 8-27 раз на боевых блоках. Перезамерить на заторном блоке с живой заявкой; согласовать с потребностью А1v3 (см. порядок).
Приёмка боем: (а) строка «CHAIN-INDEX ПРИЁМКА(60с): блоков=N>0 полных=M>0 дыр=0 ... ВЕРДИКТ: ЖИВ» на боевом хосте, ПЛЮС отсутствие молчаливой заморозки — ERROR при fresh=False. (в) валидна ТОЛЬКО после (i) фикса хэша и (ii) ОДНОГО запроса eth_getBlockReceipts на выбранном узле индекса с журналированием «метод поддержан» — иначе index_hits=0 нечитаем. Число: за сутки «#109 квитанции: polls_saved=B>0 index_hits=C>0». (б) на fat-окне: «SPECFIRE ПОЗИЦИИ blk=...» при probe_no_agg==0 и тождестве probe_landed=idx_off+uncovered+no_transit+foreign+judged.

Читающая механика близка к годной (гарды незнания закрыты по-настоящему, rc=2 существует, залповый тег и блок отправки есть), но вердикты обоих замеров невалидны, а стреляющая часть несёт самую тяжёлую находку раунда по последствиям.

=== А1v3 — ДОРАБОТАТЬ ===
Арифметика честная и воспроизведена (7/10, $67 753=56.7%, порог по сырью, вход честно переведён на n_tx(B-1)), откат снимает механизм. Но два детерминированных nonce-блокера (оба воспроизведены мной запуском) и разрыв тракта кормления.
Блокеры по важности:
1. Пустой склад + смена уровня = пересборка от отставшего pending: очередь [50,51,52] вместо [55,56,57] — прямая регрессия теста 10, ровно 31 коллизия replacement-underpriced 11.08, триггер совпадает с денежным окном. Фикс — одна строка (max(_VOLLEY_NONCE, pending) как в ветке 1411).
2. resign_ladder_tip замещает очередь целиком и выбрасывает запись, возвращённую отказом рассылки — дыра в nonce, нога виснет до таймаута ~180с. Фикс: слияние по nonce либо подпись под локом как в presign_ladder.
3. Тракт кормления не существует: Г2 читает B-1 денежных блоков ЛЕГКО (5/6 без интересных логов) — tips не строятся, режим не наступает в целевых блоках. Нужен контракт: «греть блок целиком, пока TIP_REGIME=1» — но это упирается в GIL-major Г2 (40мс разбора в призовом окне на одном ядре). Контракт обязан разрешить ОБЕ стороны разом: лёгкая выжимка tips без полного json-разбора либо честное признание зависимости от 30с-окна прогрева. Один владелец на этот шов.
4. Самозагрязнение (унаследовано из HIST-ревью, в ревью А1v3 отсутствует): мода B-1 на 53-84% состоит из НАШИХ проб в 11/50 блоков — лестница замыкается на собственную стену. Фильтр своих tx по to — одна строка.
5. Деградационная логика не защищена стендом: мутации R5/R6/R7/R10 (снос лестницы аудитом, объявка причины, вызов regime_fn, счётчики) проходят при 101/101 зелёных — текстовые assert'ы по исходнику заменить поведенческими; у механизма нет пульса вне затора («жив»=«мёртв» в журнале).
6. Противоречие осей гейта: пакет закоммичен с n_tx(B-1)>=1000 (6/10, теряет 43% денег по перепроверке HIST), а рабочая ось по данным — уровень/доля моды B-1 (мода>пола: 7/10, 99.9% денег; доля>=50%: 15/15). Plan.md уже противоречит замеру. Назначить одного владельца сведения осей до внедрения — иначе два пакета повезут два гейта в один файл.
Приёмка боем: строка «TIPREGIME включён: блок B-1 N, n_tx M, ступени ...» + regime_resigns/regime_sigs>0 в том же окне (предусловие), затем от Г2: probe_tip_match>0 в заторных блоках при включённом режиме против 0 у статики в тех же блоках, ПЛЮС доля ног, реально несущих уровень в решающем блоке (сходимость 5.5с замерена — 6/6 покрытия это потолок предиктора, не механизма).
