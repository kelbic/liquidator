## Что ОПРОВЕРГНУТО: «убрать prepare_fast» — не рычаг
- **`prepare_fast` уже zero-RTT** (`hotpath.py:747-778`): params из `_FULL_PARAMS_CACHE`, state от
  caller, `direct_swap` = локальный ABI-encode, fee из fb-хедера, gas из кэша. Цена — только Python-CPU
  (микросекунды), НЕ ~130мс. Убрать = сэкономить микросекунды.
- **«Полный in-memory флип / слой 2» — НЕ нетронутый рычаг.** Слой 1 (feed-цена, 0 RTT) и слой 2
  (`read_positions_cached`, 0 RTT) УЖЕ в бою; пол +46 измерен ИМЕННО с ними. Это содержимое +46, не апгрейд.
- Канарейка стреляет в `if not ready:` (`hotpath.py:991`) — после гейта цены + read + `_flips`,
  включает sign+send. На send-оси она даже ПЕССИМИСТична (не шлёт fb-fee → +2 Alchemy-RTT; пропускает
  SEND-3 raw-броадкаст). Т.е. её оптимизм = ровно исключённый prepare, частично гасится медленным send.

## Где на самом деле сидит +46
1. **Сеть (доминанта):** WS-инжест + brotli/JSON-декод транслята (публичный Flashblocks WS) + RTT
   отправки к секвенсеру.
2. **`_flips` по всему набору** (~1400 борроверов cbBTC, не пруненный) — CPU внутри пола (`hotpath.py:194-206`).
3. **Остаточный preconf-RTT** для рынков того же agg с oracle≠hint_oracle (`hotpath.py:906-909`).

### 🔴 SEND-3 был МЁРТВ: секвенсер отдаёт 403 на urllib

ПРИНЯТ. Т.е. `_post_raw_tx` (весь SEND-3 raw-броадкаст в секвенсер — сам путь гонки) получал бы 403
на КАЖДУЮ отправку и молча деградировал в Alchemy-only. Не всплыло, потому что боевых dispatch не
было ни одного (`DIAG seq-send` за 14д = 0 строк) — SEND-3 никогда не работал вживую.
Фикс: `_post_raw_tx` на requests.Session (UA `python-requests` проходит).
