# MONAD_ANALYSIS — анализ порта бота ликвидаций (kelbic/liquidator) на Monad и оценка +EV

> Дата: 2026-07-09. Подготовлено по запросу: «проанализируй код, прочитай каноникал Monad с GitHub,
> посмотри STATE.md и DOCS, предложи улучшения; можно ли найти экономическую обоснованность и +EV
> для запуска бота и участия в контесте ликвидаций?»
>
> Примечание по именам: репо `kelbic/monad-liquidator` на GitHub не существует; анализ сделан по
> живому боту **`kelbic/liquidator`** (Base / Morpho Blue, вооружён в проде) как кандидату на порт.
> Среда этой сессии не имеет доступа к RPC/Morpho API (egress-политика) — все ончейн-величины по
> Monad собраны из первоисточников (docs.monad.xyz через GitHub-зеркала, category-labs/monad,
> category-labs/monad-bft) и вторичных источников с адверсариальной верификацией; что не удалось
> подтвердить — помечено. Всё, что требует ЖИВОГО замера, вынесено в «План замеров» (§6).

## 0. TL;DR

1. **Порт возможен и дешевле, чем кажется:** ~60% кода переносится как есть (вся Morpho-математика,
   Multicall3, blue-api с chainId 143, nonce/дедуп/kill-switch-машинерия). Умирает весь
   Base-специфичный слой «подсмотреть до блока» (flashblocks, preconf, sequencer, OCR-offset-676) —
   и это **выравнивание поля, а не потеря**: на Monad этого канала нет ни у кого (нет публичного
   мемпула вовсе). Оценка: 1,5–3 недели работы.
2. **Экономика реверта перевёрнута:** Monad списывает **gas_limit, а не gas_used**. Стратегии
   спама/probing наказаны протоколом → поле смещено в пользу «точный детектор + один выверенный
   выстрел» — ровно наш профиль. Но и наши паддинги лимита (×1.2, max(...,500k)) становятся
   прямым убытком: лимит жать, floor считать с base fee.
3. **Aave-on-Monad (крупнейший пул, $100M+ за 48ч) — почти закрыт для нас:** первый деплой Aave
   с Chainlink SVR с первого дня — право бэкрана оракул-апдейта ПРОДАЁТСЯ через приватный аукцион,
   ~73% ценности ликвидаций изымается (65% протоколу). Это «gated 0x322e1d53» ещё раз, только
   в масштабе всего Aave.
4. **Открытая ниша — Morpho/Euler/Curvance на Monad** (суммарно ~$150–200M TVL; публичных
   свидетельств гонок ликвидаций ноль за 7 месяцев, но ончейн-поле НЕ пустое — через
   FastLane-аукцион прошло 1.47M транзакций; тонкость конкуренции мерить, не постулировать).
   Плюс **новый класс, недоступный на Base:** pull-оракулы (Pyth и др.) позволяют самому
   запостить цену и ликвидировать **одной атомарной транзакцией** — «атомарный класс»,
   который на Base был структурно закрыт бандл-каналом, на Monad открыт любому быстрому.
5. **Вердикт по EV: знаменатель не измерен — решение принимать рано.** Лендинг-TVL Monad
   (~$300–450M на весь чейн) на 1,5–2 порядка меньше Base; грубая вилка бонус-пула открытых
   протоколов — единицы–десятки тысяч $/мес в спокойном рынке (не бэнкабельно без замера).
   Правильный ход — тот же, что на Sonic-треке: **2–4 недели read-only замера знаменателя**
   (план в §6, все инструменты уже есть в репо, адаптация минимальна), стоимость ~$0–50/мес.
   Гейт на порт: измеренный достижимый пул ≥ $3–5k/мес.
6. **Независимо от Monad:** ревью нашло **реальные баги в боевом Base-боте**, два — high
   (необратимый nonce-gap после receipt-timeout; SQLite-контеншн, рвущий wss-петлю в каскад).
   Чинить их стоит до любых портов (§5.1).

Формального «контеста ликвидаций» (программы/приза для ликвидаторов) на Monad НЕТ: $15M от
Monad Foundation — это supply/borrow-инсентивы Aave-рынку. «Контест» здесь — обычная гонка
ликвидаторов; на открытых протоколах она предположительно тонкая (замер — §6.3).

## 1. Каноникал Monad: что важно для бота ликвидаций (первоисточники)

Источники: docs.monad.xyz (полное markdown-зеркало в GitHub, коммит `cd2e597` репо
`le-dat/chat-service`; сайт напрямую из этой среды недоступен), `category-labs/monad`
(execution, C++/Rust), `category-labs/monad-bft` (консенсус, Rust), блоги category.xyz.

### 1.1 Темп и финальность
- **Блок каждые 400 мс**; спекулятивная финальность ~1 слот (Voted), полная ~2 слота (**800 мс**),
  реорг финализированного невозможен; спекулятивный откат — только при эквивокации лидера (редко,
  но код обязан переживать).
- MonadBFT — пайплайновый ротационный BFT: **лидер меняется каждый блок** по stake-weighted
  расписанию на эпоху (50k блоков ≈ 5,5 ч).
- **Асинхронное исполнение**: консенсус упорядочивает транзакции ДО исполнения (лаг D блоков,
  testnet D=3). Нода исполняет блок сразу по получению — receipt/состояние доступны локально
  почти сразу.
- RPC-теги: `latest` = Voted (в доках помечено «меняется на Proposed»), `finalized` = Finalized.
  `eth_call('latest')` уже читает спекулятивное состояние на 1–2 блока раньше финализации —
  это «бесплатный preconf».

### 1.2 Газ (критично, ломает Base-привычки)
- **Списывается gas_limit, а не gas_used** (анти-DoS при асинхронном исполнении). Реверт стоит
  ПОЛНЫЙ лимит; завышенный лимит — прямая переплата на каждой tx.
- EIP-1559-подобная механика: динамический base fee (таргет 160M из 200M блочного лимита,
  контроллер «растёт медленно, падает быстро»), **min base fee = 100 MON-gwei**; per-tx лимит 30M.
- **Репрайсинг опкодов**: cold SLOAD 2100→8100, cold account access 2600→10100, SSTORE нового
  слота 20000→127900, CREATE 32000→160000. Ликвидация+своп легко 1,5–3M gas по Monad-ценам.
- В деньгах пока копейки: при MON≈$0.02 транзакция с лимитом 1M gas ≈ 0.1 MON ≈ **$0.002**
  (min base fee). Но экономика ревертов и лимитов — вопрос дисциплины, а не нуля.
- **Reserve balance** (~10 MON на аккаунт): на приёме валидируется worst-case `gas_bid×gas_limit`
  за окно k блоков — при `MAX_INFLIGHT=5` параллельных tx кошелёк должен нести резерв под ВСЕ,
  иначе отказ на приёме. Новый режим отказа, которого на Base нет.

### 1.3 Мемпул, ордеринг, MEV
- **Глобального мемпула НЕТ.** RPC-нода форвардит tx напрямую следующим N лидерам (testnet N=3)
  через RaptorCast; `newPendingTransactions` не существует. Чужих pending-ликвидаций не видно,
  и тебя не видно. Слой 1 (декод transmit из tx-стрима) на Monad мёртв — у ВСЕХ.
- **Ордеринг в блоке**: дефолт клиента — Priority Gas Auction (сортировка по убыванию priority
  fee). Но «leaders add transactions as they see fit» — допускаются сайдкары.
- **FastLane/Atlas — ЖИВ на mainnet** (верификация ОПРОВЕРГЛА раннюю версию «только shMONAD»):
  Atlas v1.6.4 (`0x2DA28fe...875E8`) и FastLaneAuctionHandler (`0xD32EdF...FFF58`, **1.47M
  транзакций**) числятся в официальном реестре Monad Foundation (`monad-crypto/protocols`,
  mainnet/fastlane.jsonc, `"live": true`); валидаторский сайдкар `fastlane-sidecar` считает
  ордеринг через этот mainnet-контракт; заявлено ~118/198 валидаторов. То есть на значительной
  доле слотов внутриблоковый приоритет ПРОДАЁТСЯ через аукцион, а не чистый PGA. Chainlink
  купил Atlas (янв 2026) и везёт SVR на новые чейны через него. (README
  `fastlane-contracts` «testnet-only» отстаёт от их же atlas-config — источник ранней ошибки.)
- Аналога Flashbots-бандлов нет; encrypted mempool — research, не прод.
- **Колокация невозможна по построению**: ~200 валидаторов в десятках стран, лидер ротируется
  каждые 400 мс. Оптимум — bare metal в точке минимального среднего RTT до stake-weighted центра
  масс валидаторов.

### 1.4 Каналы данных и нода
- **Стандартные `newHeads`/`logs` с клиента v0.14.0 (01.04.2026) отдают Proposed-блоки** —
  спекулятивный канал доступен любому WS-подписчику (верификация ОПРОВЕРГЛА «finalized-only»:
  это было верно до фев–апр 2026; страницы rpc-differences и доки провайдеров отстают; в
  master `COMMIT_STATE_FILTER = Proposed`, monad-rpc/websocket/handler.rs:59). Отдельные
  `monadNewHeads`/`monadLogs` дают то же + blockId/commitState и повторные апдейты на каждой
  стадии. Следствие: детекционного эджа «просто за счёт подписки» нет ни у кого — решают RTT
  до ноды-источника, точность и send-путь.
- **Execution Events SDK** (shared-memory event ring на своей ноде, C/C++/Rust,
  `category-labs/monad` → `monad-event-ring`) — самый ранний легальный сигнал в экосистеме:
  события в момент локального исполнения, до финализации.
- Своя full-нода: bare metal, 16 ядер ≥4.5GHz, 32GB+, 2×2TB NVMe, 100 Mbit/s — ~$150–350/мес
  (Latitude/OVH/Hetzner-класс). Облака официально не поддержаны.
- RPC-отличия: `eth_getLogs` — узкие диапазоны (1–10 блоков рекомендовано); nonce-gap не
  отклоняется сразу на `eth_sendRawTransaction` (нонсы вести локально — наша машинерия уже так
  делает); `eth_maxPriorityFeePerGas` временно хардкод 2 gwei; историческое состояние на
  full-нодах отсутствует (для бэктестов — archive-провайдер).
- EVM Pectra-уровня, контракты до 128kb, **Multicall3 на каноничном 0xcA11...CA11** — наш
  батчер переносится без правок.

## 3. Карта портируемости кода (по файлам)

### Переносится как есть (~60% строк)
- `chain/simulate.py` целиком (shares-математика, health_from, max_borrow — Morpho Blue тот же
  байткод), `_seized_exact`/`_cap_repaid_shares`, `strategy/pnl.py` (LIF из LLTV).
- `chain/multicall.py` (Multicall3 тот же адрес), `chain/morpho.py` + `main.fetch_candidates` +
  warm-start (blue-api с chainId 143; `MEGA_MARKETS`/`INCLUDE_MARKETS` обнулить под Monad).
- Send-слой: EIP-1559 подпись, `_LOCAL_NONCE`/`_RECENT_SENDS`/inflight/дедуп/батч с
  последовательными нонсами — переносится дословно и остаётся нужным (nonce-gap на Monad не
  отклоняется RPC — локальный учёт обязателен).
- `store.py`, `strategy/guard.py` (kill-switch), `config.py`-каркас, `alerts.py`.
- Poll-детектор цен `_poll_prices`/`_poll_changed`/`_flips`/`_net_gate` — становится ОСНОВНЫМ
  триггером (поверх `monadNewHeads`).

### Умирает (Base-эксклюзив) — удаление, не переписывание
- Flashblocks wss + brotli + `basefee_of`/`block_number_of` из fb-кадров.
- Preconf-слой (`mainnet-preconf.base.org`, `block='pending'`) — на Monad `latest` уже
  спекулятивный; seams инжектируемые, вырождается в «обычный RPC».
- Слой 1: FORWARD_SEL + offset 676 + `_SHADOW_SCALE` + bare-match — публичного tx-стрима нет.
- SEND-3 (секвенсер-эндпоинт) → параллельный broadcast в несколько RPC (хелпер тот же, URL другие).
- Aerodrome Slipstream (Base-native), KyberSwap (на Monad не подтверждён).

### Переписывается / проектируется заново
1. **Блочный триггер**: `monadNewHeads`/`monadLogs` (спекулятивные), в идеале — своя нода +
   Execution Events SDK (event ring) как источник событий оракулов/ликвидаций.
2. **Газ-экономика**: floor-математика с base fee (на Base игнорировался как ~0), `realized_econ`
   по `gas_limit×price` (не gasUsed), паддинги лимита ×1.2/max(...,500k) → точный лимит,
   учёт reserve balance при параллельной отправке.
3. **Маршруты свопа**: Uniswap v3 на Monad официально есть (другие адреса) — `_pack_path`/
   селекторы переносятся; таблицу пулов и глубину перемерить (методика верификации пулов 07-08).
4. **Оракульный слой**: если рынки Morpho-Monad на Chainlink-push — `resolve_feeds` переиспользуем
   с новой картой; если на Pyth/RedStone-pull — новый слой «подписка на Hermes/шлюз → атомарный
   push+liquidate» (см. §4.2). Это не порт, а НОВАЯ альфа.
5. **Тайминги**: все секундные константы пересчитать в блоки (400 мс): refresh 60с = 150 блоков,
   `_POSITION_CACHE_MAX_AGE_SEC=6с` = 15 блоков, receipt-timeout 120с → секунды.
6. **Каркас конкурентности**: thread-per-block/thread-per-transmit при 2,5 блоках/с даст
   наслоение — консолидация в пул воркеров/asyncio (~200 строк каркаса; см. §5.2).
7. **Контракт**: `Liquidator.sol` заведётся на Morpho-Monad **без правок** (адрес в конструкторе;
   Pectra-совместим; адрес синглтона сверить по docs.morpho.org перед деплоем). Для Aave —
   отдельный контракт ~150–200 строк (flashLoanSimple → liquidationCall → swap → repay+premium
   0.05%), ~50% хелперов переиспользуются; но см. SVR-оговорку.

**Оценка: 1,5–3 недели** (большая часть — удаление Base-слоёв, пересбор констант/маршрутов и
ре-верификация рынков/оракулов; новая логика — только pull-оракульный путь и газ-дисциплина).

## 4. Конкурентная механика на Monad: чем игра отличается от Base

### 4.1 Сходства с нашей текущей игрой
- Публичного мемпула нет ↔ Base с приватным секвенсером: конкуренция = state-race
  (скорость чтения нового состояния) + ставка priority fee + канал доставки.
- PGA по priority fee внутри блока ↔ первый флэшблок Base.
- Наша дисциплина «точный детектор, floor, kill-switch» переносится идеологически без изменений.

### 4.2 Отличия — и почти все в нашу пользу
1. **Спам наказан протоколом** (gas_limit-биллинг + carriage cost + reserve balance). На Base
   спам-MEV >50% газа блоков и 2 сёрчера держат >80% спама; на Monad эта стратегия дорогая по
   построению. Поле смещено к latency+accuracy — нашей модели.
2. **«Атомарный класс» открывается.** На Base 25–31% ликвидаций (gap≤2, приватный бандл) были
   структурно недостижимы. На Monad, если рынок на pull-оракуле (Pyth/RedStone-pull), «оракул
   обновился → позиция под водой» превращается в «МЫ обновляем оракул и ликвидируем одной tx».
   Триггер у нас в руках: смотрим оффчейн-поток цен (Pyth Hermes, 400мс-апдейты), считаем HF
   заранее, атомарно постим цену+ликвидацию. Гонка сдвигается в «кто быстрее увидел крест в
   оффчейн-потоке и доставил tx лидеру» — это ровно наш суб-блочный профиль.
3. **Нет колокации** — не нужно жить рядом с секвенсером; уровень поля равнее, чем на Base.
4. **Event ring на своей ноде** — легальный самый ранний сигнал; аналог нашего слоя 1, но
   доступный любому, кто поставит bare-metal ноду (~$150–350/мес). После v0.14.0 стандартный
   WS у провайдера тоже спекулятивный — порог входа в детекцию низкий для всех; нода даёт
   в основном send-путь (прямой RaptorCast-форвардинг лидерам) и event ring.
5. **Поле молодое, но НЕ пустое**: кейсов гонок в паблике ноль за 7 месяцев, aPriori-аукцион
   не подтверждён — но FastLaneAuctionHandler на mainnet накопил **1.47M транзакций** (какая
   доля — ликвидации, не измерено), а приоритет на ~60% слотов продаётся через сайдкар.
   «Тонкость» конкуренции — гипотеза до ончейн-замера концентрации победителей (§6.3), не факт.
   Окно, если оно есть, закроется по мере прихода Base-игроков за Aave-объёмом.

### 4.3 Что против нас
1. **SVR на Aave** — крупнейший пул изъят из открытой гонки с первого дня (структурный тренд:
   Chainlink купил Atlas и целенаправленно везёт OEV-изъятие на новые чейны). Такая же судьба
   может настигнуть и другие протоколы (Morpho-рынки на SVR-фидах — наш `EXCLUDE_ORACLES`
   уже это фильтрует на Base).
1a. **FastLane-аукцион на ~60% слотов**: если внутриблоковый приоритет на большинстве блоков
   продаётся, модель «латентность + PGA-ставка» работает только на слотах без сайдкара; для
   стабильного win-rate может потребоваться онбординг в аукцион (комиссии/биды режут маржу).
   Механика аукциона (cadence, латентность ставки, комиссия, покрывает ли он Morpho-ликвидации
   или только oracle-backrun) — не изучена, в план замеров.
2. **Знаменатель маленький**: весь лендинг Monad ≈ 1/4 одного cbBTC/USDC на Base. Даже при
   нулевой конкуренции пул бонусов открытых протоколов в спокойном рынке — вероятно единицы
   тысяч $/мес (вилка неизмерена!).
3. Реверты стоят полный лимит — цена ошибки детектора выше, чем на Base (в абсолюте копейки,
   в дисциплине — существенно).
4. MON-экономика: стимулы иссякнут, borrow-спрос может сдуться; цена MON ~$0.02 около/ниже ICO.

## 5. Предложения по улучшению

### 5.1 Баги боевого Base-бота (чинить независимо от Monad; два — high)
> **СТАТУС 07-11: пункты 1 и 2 ИСПРАВЛЕНЫ коммитом `78171cb` (07-09, в проде с 22:07).**
> П.1 — `_LOCAL_NONCE.pop` в timeout-ветке (execute.py:582); поведение ДОКАЗАНО смоуком 07-11
> (timeout → инвалидация → loss → inflight-слот освобождён → следующий dispatch пере-читает RPC
> и закрывает дыру). Остаточный кейс — путь `wait_receipts=False` (fire-and-forget, СЕЙЧАС НЕ
> ИСПОЛЬЗУЕТСЯ): там receipt-loop нет и pop не сработает — закрывается receipt-коллектором,
> пункт 6 P210_CONTROL_PLAN. П.2 — WAL+busy_timeout в store.py:55-56. П.3 (MED SEND-3 race) — ОТКРЫТ.
1. **[HIGH] Необратимый nonce-gap** (`chain/execute.py:575`): ветка receipt-timeout не
   инвалидирует `_LOCAL_NONCE`, а `_reconcile_nonce` берёт `max(rpc, local)` и никогда не
   опускает. Дропнутая из мемпула tx (base-fee спайк выше `fb*2+tip`, evict) → локальный nonce
   навсегда впереди чейна → все последующие отправки queued-с-гэпом, бот «жив», но не майнит
   ничего до рестарта. Фикс: в ветке timeout инвалидировать `_LOCAL_NONCE` / сверять
   `get_transaction_count('latest')` и принимать меньшее при отсутствии pending.
2. **[HIGH] SQLite-контеншн рвёт wss-петлю в каскад** (`store.py:47`): соединение-на-вызов без
   WAL/busy_timeout при конкурентных писателях (блочная петля + hot-воркеры). `database is
   locked` пролетает до внешнего except и рвёт wss (3с+ реконнект слепоты ровно в каскад).
   Фикс: WAL + busy_timeout + фоновая писательская очередь; `realized_today` кэшировать в памяти.
3. **[MED] SEND-3 race** (`execute.py:277`): raw-broadcast в секвенсер стартует ДО основного
   send; при исключении основного пути tx уже ушла, но `_RECENT_SENDS`/inflight не выставлены →
   дубль в следующем блоке (гарантированный реверт), расход невидим kill-switch. Фикс: метить
   дедуп/inflight ДО broadcast (hash детерминирован от подписи).
4. **[MED] Синхронный Telegram в петле** (`alerts.py:26`): urllib timeout=10 из блочной петли;
   в каскаде каждый новый (mid,borrower) — новый antiflood-ключ = новый блокирующий вызов до 10с.
   Фикс: очередь + фоновый sender. Плюс: тихий `return False` при пустом конфиге — уже стоил
   недель мёртвого алертинга (инцидент TG_ADMIN_ID); при MODE=execute — громкий self-test на старте.
5. **[MED] Kill-switch частично слеп** (`store.py:79`): `realized_today` учитывает только
   `submitted:%` и net на момент dispatch; газ замайненных ревертов не входит в дневные лимиты.
   Фоновый receipt-коллектор — обязательный предохранитель ДО включения standing-спама (P2-10).
6. **[MED] CLI `build_covered_markets.main()` не передаёт `exclude_oracles`** — ручная
   регенерация covered_markets.json (ровно шаг 2 CBBTC_PLAN) молча теряет SVR/OEV-фильтр.
7. Мелочи: утечка `_POSITION_CACHE` (ушедшие заёмщики не эвиктятся), TOCTOU inflight-гейта
   (мягкий кап `N_workers×max_inflight`), `Market(**m)` падает на неизвестном ключе JSON
   (crash-loop), `_loan_price()` молча кэширует 1.0 для нестейблов (отчёты врут на порядки),
   `.env.example` драматически отстал от config.py, ARCHITECTURE.md описывает несуществующую
   фазу («main.py вхолостую», Dune как источник) — при правиле «новые сессии читают доки,
   а не разведывают» это операционный риск.

### 5.2 Улучшения перформанса (полезны на Base, обязательны для 400мс-чейна)
- Не держать `_SEND_LOCK` через сетевые RTT (подпись+broadcast параллельно вне лока).
- Параллелить `prepare_liquidation` по кандидатам (сейчас каскад сериализуется ДО dispatch;
  комментарий «Parallel so a cascade isn't serialized» покрывает только dispatch).
- Консолидация thread-спавнов в пул воркеров (при 2,5 блоках/с thread-per-event наслаивается).
- Fee-параметры из кэша для всех путей (сейчас блочный путь = 2 RTT на КАЖДУЮ tx под локом).
- Адаптивный tip от размера приза (на Monad priority fee — единственный аукционный рычаг).
- Убрать фиксированные 10мс drain-паузы из newHeads-пути (2,5% блочного времени Monad).

### 5.3 Контракт
- Allowlist роутеров для `swapTarget` (сузить blast radius компрометации owner-ключа до нуля).
- Ownable2Step + проверка `newOwner != 0` (одна опечатка сейчас необратимо теряет контракт).

- `receive()` + sweepEth + sweepMany (маршрут с unwrap-ETH сейчас ревертнёт).
- Офлайн-тесты с локальным деплоем Morpho (vm.etch/deployCode): негативные кейсы NotMorpho/

  тесте проходит на ЛЮБОМ реверте.
- `_call()` не проверяет наличие кода по адресу токена (вызов EOA «молча успешен»).

### 5.4 Monad-специфичные новые компоненты (если гейт §6 пройден)
- **Pyth/RedStone pull-слой**: подписка на оффчейн-поток (Hermes), предрасчёт HF по кандидатам,

## 6. План замеров знаменателя (read-only, 2–4 недели, до любого порта)

Всё в духе наших правил: без транзакций, без ключей, только чтение публичного RPC + blue-api.
С VPS (не из этой сессии — тут egress закрыт).

1. **Карта рынков Morpho-Monad** (blue-api, chainId 143): рынки, borrow, LLTV/LIF, оракул
   каждого рынка (push/pull/SVR) — адаптация `build_covered_markets.py` (сменить chainId,
   обнулить Base-списки). Аналогично Euler/Curvance (subgraph/ончейн).
2. **Ликвидации за 30–60 дней**: `getLogs` Liquidate на синглтоне Morpho-Monad узкими чанками
   (лимит диапазона!) + LiquidationCall Aave с 07-02 — адаптация `competition_report.py` /
   `liq_daily_histogram.py`. Выход: **$/мес бонус-пула по рынкам** — главный гейт.
3. **Концентрация победителей** (наша метрика контестабельности с Sonic-трека): уникальные
   ликвидаторы, доля топ-1/топ-3 по рынкам. Пусто/1–2 адреса = окно реально.
4. **Атомарность**: tx-index ликвидации vs tx-index оракул-апдейта в том же блоке (методика
   `winner_xray`, узкий getLogs). Доля «same-tx» (pull-атомарные), same-block, lag≥1 — решает,
   какой слой строить первым.
5. **Доля ревертов/спама** в ликвидационных попытках (receipt status по кандидатам) — уровень
   конкуренции и работает ли анти-спам экономика.
6. **Латентная разведка**: RTT до публичных RPC с наших площадок (адаптация `rtt_probe.py`),
   поддержка `monadNewHeads`/`monadLogs` у Alchemy/QuickNode/dRPC, тайминг Finalized vs Proposed.
7. **SVR-фиды Aave-Monad**: список фидов под SVR, fallback-задержка публичного апдейта (ниша
   «SVR-аукцион не отработал»), условия онбординга сёрчеров; покрывает ли OEV-аукцион
   Morpho-рынки или только Aave.
8. **Exit-ликвидность** (пробел критика): глубина DEX Monad для сброса залогов (wstETH, weETH,
   cbBTC, sUSDe, MON…) — кривая слиппажа QuoterV2-методикой (как cbBTC 07-09); наличие и цена
   flash loans (Morpho built-in есть; Aave flashLoanSimple 0.05%). Определяет потолок размера
   профитной ликвидации N — при TVL чейна ~$450M крупные призы могут быть убыточны на выходе.
9. **Механика FastLane-аукциона** (пробел критика): доля stake-weight под сайдкаром, cadence и
   латентность подачи ставки, комиссия, идут ли через него ликвидации Morpho или только
   oracle-backrun; разбор транзакций AuctionHandler `0xD32EdF…FFF58` (какая доля — ликвидации).
10. **Боевая экономика попытки** (пробел критика): фактический base fee/priority fee в реальных
   гонках (не floor 100 MON-gwei пустой сети), минимально безопасный gas_limit ликвидации
   (риск out-of-gas при срезании), break-even win-rate при списании полного лимита.
11. **Устойчивость потока** (пробел критика): borrow-утилизация Aave/Morpho после затухания
   стимулов ($15M на 12 мес), волатильность залогов (без волы поток ликвидаций нулевой при
   любом TVL). Плюс операционная цена второго деплоя: поддержка Base-бота не должна просесть
   (отдельный кошелёк/ключ/custody MON, on-call на чейне с 400мс блоками, критерии wind-down).

**Гейты решения (все — по данным, не по ощущению):**
- (G1) Достижимый бонус-пул открытых протоколов ≥ **$3–5k/мес** → порт +EV против
  ~$150–350/мес bare-metal + 1,5–3 недель работы. Ниже → paper-наблюдение или стоп.
- (G2) Концентрация победителей на целевых рынках ≤ ~60% (поле не занято одним ботом).
- (G3) Если доминирует pull-класс — сначала строить push+liquidate-слой, не порт hot-path.
- (G4) Exit-ликвидность: слиппаж на целевом размере приза ≤ половины бонуса (иначе рынок
  из покрытия, как cbLTC/EURC-урок на Base).

## 8. Ответ на вопрос «есть ли +EV»

**Сегодня честный ответ: EV не определён — и определим дёшево.** Структура рынка Monad
благоприятнее Base для нашей архитектуры (нет мемпула ни у кого, спам наказан, атомарный класс
открывается pull-оракулами, конкуренция тонкая, вход ~$150–350/мес), но знаменатель мал
(лендинг всего чейна ≈ 1/4 одного нашего Base-рынка) и крупнейший пул (Aave) изъят SVR-аукционом
с первого дня. Это зеркало Sonic-вывода: «технически можем — экономически надо мерить».

Рекомендуемая последовательность:
1. Починить high-баги боевого бота (§5.1.1–5.1.2) — деньги под риском уже сейчас.
2. Запустить замер знаменателя Monad (§6) с VPS — read-only, ~неделя работы, $0 капитала.
3. По гейтам G1–G3 решать порт. Если G1 пройден — порт 1,5–3 недели, старт в MODE=monitor
   (paper) на своей bare-metal ноде, ARM только по нашей стандартной дисциплине.
4. Окно тонкой конкуренции конечно (Atlas/aPriori на подходе, Base-игроки придут за
   Aave-объёмом) — если мерить, то сейчас; решение о порте не откладывать дольше 1–2 месяцев.
